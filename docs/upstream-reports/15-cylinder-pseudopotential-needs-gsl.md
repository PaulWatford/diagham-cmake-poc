# 15. ParticleOnCylinderPseudopotentialHamiltonian: fail clearly without GSL instead of undefined behaviour

Purpose: the report to send to the DiagHam authors with the diff `patches/upstream/15-cylinder-pseudopotential-needs-gsl.diff`.
Source: commit `2e67a4b3a` on `main` (generated by `scripts_cmake/upstream_pack.py`, do not edit; edit the commit message or the fix index instead).

**Base**: SVN r4493. **Files**: `FQHE/src/Hamiltonian/ParticleOnCylinderPseudopotentialHamiltonian.cc`.

## What, why, how it was verified

PseudopotentialMatrixElement and LineChargeMatrixElement are entirely
inside #ifdef HAVE_GSL; without GSL the non-void functions fell off the
end, which showed up as "*** stack smashing detected ***" in every run of
FQHECylinderFermionsTwoBodyGeneric (and any program using this
Hamiltonian) built without DIAGHAM_USE_GSL. Now an #else branch prints
which build option is needed and exits 1. Behaviour with GSL unchanged.

Found while writing the cylinder zero-mode goldens (defect register U28).
