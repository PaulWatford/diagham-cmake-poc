# 17. ParticleOnCylinderCoulombHamiltonian: fail clearly without GSL instead of undefined behaviour (U33)

Purpose: the report to send to the DiagHam authors with the diff `patches/upstream/17-cylinder-coulomb-needs-gsl.diff`.
Source: commit `a0c9a80ee` on `main` (generated by `scripts_cmake/upstream_pack.py`, do not edit; edit the commit message or the fix index instead).

**Base**: SVN r4493. **Files**: `FQHE/src/Hamiltonian/ParticleOnCylinderCoulombHamiltonian.cc`.

## What, why, how it was verified

CoulombMatrixElement and LineChargeMatrixElement are entirely inside
#ifdef HAVE_GSL; without GSL the non-void functions fell off the end,
which showed up as a segmentation fault right after "Hilbert space
dimension" in every run of FQHECylinderFermionsCoulomb built without
DIAGHAM_USE_GSL (the default preset). Now an #else branch prints which
build option is needed and exits 1. Behaviour with GSL unchanged. The
same defect and the same fix as U28 (ParticleOnCylinderPseudopotentialHamiltonian).

Found while writing the cylinder goldens (defect register U33).
